# سجل شهادات المعلمين

واجهة عربية على GitHub Pages، وخدمة Node.js منفصلة لحسابات المعلمين وقاعدة SQLite، وشهادات PDF في Google Drive المدرسة.

## الحالة

هذه نسخة تنفيذ أولية تحتاج إعداد الخدمة الخلفية، تفويض Google، إنشاء الحسابات، واختبار قبول قبل استقبال بيانات حقيقية. لا توجد حسابات افتراضية أو كلمات مرور مضمّنة. الواجهة تبين أن النظام غير مفعل عندما يكون رابط الخدمة فارغًا.

## نشر الواجهة

1. افتح Settings → Pages في المستودع.
2. اختر GitHub Actions ضمن Source.
3. شغل Publish school portal من Actions إذا لم يبدأ تلقائيًا.
4. الرابط المتوقع بعد نجاح النشر: https://coolmanx88.github.io/school-certificates/

ينشر workflow أربعة ملفات الواجهة فقط. لا ينشر قاعدة البيانات أو ملفات الخدمة الخلفية.

## تشغيل الخدمة الخلفية

تحتاج استضافة Node.js 24 عبر HTTPS مع قرص دائم، وليست GitHub Pages. SQLite مناسب لهذه المدرسة على نسخة خادم واحدة. لا تشغل نسخ خادم متعددة على ملف قاعدة البيانات نفسه. يجب إعداد نسخ احتياطي يومي باستخدام SQLite backup API أو آلية نسخ متسقة، واختبار الاستعادة.

داخل backend:

```sh
npm ci
node --env-file=.env server.mjs
```

جهز ملف .env محليًا من .env.example، أو عرّف المتغيرات من مدير الأسرار لدى المستضيف. لا ترفعه إلى GitHub.

- FRONTEND_ORIGIN: https://coolmanx88.github.io (بدون مسار المستودع).
- DB_PATH: مسار على القرص الدائم، مثل /data/school.sqlite.
- IDENTITY_KEY: سر عشوائي 32 حرفًا على الأقل؛ احتفظ بنسخة آمنة ولا تغيره دون ترحيل الحسابات.
- GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET / GOOGLE_REFRESH_TOKEN: بيانات تفويض حساب المدرسة.
- DRIVE_FOLDER_ID: معرّف مجلد خاص بشهادات المدرسة.
- TRUST_PROXY: عدد وسطاء الشبكة الموثوقين لدى المستضيف؛ اتركه غير معرف عند الاتصال المباشر. ضبطه مهم لتقييد محاولات الدخول بصورة صحيحة.

ضع رابط الخدمة HTTPS العام في apiUrl بملف config.js. هذا الرابط ليس سرًا.

## ربط Drive

1. أنشئ مشروع Google Cloud تابعًا للمدرسة وفعّل Google Drive API.
2. اضبط OAuth consent screen وعميل OAuth للتطبيق، ثم فوّض حساب المدرسة مع offline access للحصول على refresh token.
3. يفضل نطاق drive.file مع مجلد أنشأه التطبيق أو تم اختياره عبر Google Picker؛ إدخال ID لمجلد موجود يدويًا لا يمنح التطبيق الوصول إليه. النطاق drive أوسع وقد يتطلب مراجعة Google؛ يحدد اختيار النطاق حسب إعداد الحساب وسياسة النشر.
4. أنشئ مجلدًا خاصًا دون مشاركة عامة. التطبيق لا ينشئ روابط عامة ولا يمنح المعلمين وصولًا إلى Drive.
5. خزّن الأسرار في الخدمة الخلفية فقط. راجع وضع تطبيق OAuth: رموز التجديد في وضع الاختبار الخارجي قد تنتهي بعد 7 أيام عند استخدام نطاقات Drive. لا تعتمد وضع الاختبار للتشغيل المستمر.
6. اختبر الرفع من حساب معلم، وافتح الشهادة من حساب المسؤول، ثم تحقق من وجود الملف في حساب المدرسة.

راجع وثائق Google الرسمية: https://developers.google.com/identity/protocols/oauth2/web-server و https://developers.google.com/workspace/drive/api/guides/manage-uploads

## إنشاء الحسابات وإعادة التعيين

أداة account.mjs تستقبل سجل JSON واحدًا من stdin: name وidentity (10 أرقام) وpassword (12 حرفًا على الأقل) وrole (teacher أو admin). شغلها على الخادم، باستخدام أداة إدارية خاصة لتمرير البيانات عبر stdin. لا تضع الهوية وكلمة المرور في معاملات shell أو المستودع. يجب إغلاق stdin بعد الإدخال.

```sh
node --env-file=.env account.mjs
```

إذا كان رقم الهوية موجودًا تُحدّث بياناته وكلمة مروره وتلغى جلساته. استخدم ذلك لإعادة التعيين. يُفرض تغيير كلمة المرور عند أول دخول، بما يشمل حساب المسؤول.

## الصلاحيات والضوابط

- المعلم: إضافة شهادة فقط بعد تسجيل الدخول وتغيير كلمة المرور المؤقتة.
- المسؤول: البحث وقراءة الشهادات وتغيير حالة المراجعة وتصدير CSV المتوافق مع Excel.
- هوية المعلم تؤخذ من الجلسة؛ لا يختار اسمًا عند رفع الشهادة.
- أرقام الهوية محفوظة كبصمة HMAC، وكلمات المرور عبر scrypt مع salt لكل حساب.
- الجلسة ساعتان ورمزها في ذاكرة الصفحة فقط؛ تحديث الصفحة يتطلب الدخول مجددًا.
- يُرفض الملف إذا لم يبدأ بتوقيع PDF أو تجاوز 25 MiB؛ فحص التوقيع لا يغني عن فحص برمجيات ضارة إذا تطلبته سياسة المدرسة.
- تكرار الملف نفسه للمعلم نفسه مرفوض ببصمة SHA-256. النسخ المختلفة أو الصور المعاد تصديرها تحتاج مراجعة بشرية.
- بيانات المعلمين، الشهادات، أسرار Google والنسخ الاحتياطية لا توضع في GitHub.

## اختبار القبول قبل الإطلاق

- معلم غير مسجل لا يدخل؛ كلمة مرور خاطئة لا تمنح الوصول.
- المعلم لا يستطيع طلب قائمة الشهادات أو ملف شهادة حتى بطلب API مباشر.
- تغيير كلمة المرور المؤقتة مطلوب قبل أي رفع أو بحث.
- PDF صالح يُحفظ، والملف الأكبر من الحد مرفوض، والتكرار مرفوض.
- المسؤول يبحث ويغير حالة المراجعة ويحمّل الشهادة ويصدر CSV.
- المجلد خاص؛ النسخ الاحتياطي والاستعادة يعملان؛ محاولات الدخول المتكررة محدودة.
- نفذ تجربة بخمسة معلمين على الهاتف والكمبيوتر قبل التعميم.

## حدود التحقق

التحقق المحلي من الكود والصلاحيات لا يثبت نجاح الربط بحساب Google أو نشر GitHub Pages. يلزم اختبار التكامل ببيئة المدرسة. لم تُجر مراجعة بصرية في متصفح ضمن هذه الجلسة.

## مدرسة الرويشدي: استيراد ملف الحسابات

جهزت مجلد المدرسة ومجلد الشهادات في Drive، وضبطت معرّف مجلد الشهادات في نموذج الإعداد. هذا لا يعني تفعيل تفويض Google.

ملف Excel خاص في Drive: ورقة الحسابات، العناوين في الصف 5، وحساب المسؤول أولًا ثم المعلمين. املأ الاسم والهوية، مع الاحتفاظ بكلمات المرور المؤقتة أو تعديلها إلى 12 حرفًا على الأقل. لا يُستورد صف بلا اسم وهوية.

على الخادم وبعد تعبئة الملف، شغّل:

```sh
node --env-file=.env import-accounts.mjs /private/school-login-accounts.xlsx
```

هذا استيراد خاص من الخادم، وليس رفعًا إلى مستودع GitHub. يستورد جميع الصفوف الصحيحة في عملية واحدة، ويرفض الملف كاملًا إذا وجدت بيانات غير صالحة أو هوية مكررة أو موجودة مسبقًا. الملف ليس قاعدة كلمات المرور الحية؛ بعد أول دخول تحفظ الخدمة كلمة المرور الجديدة كبصمة فقط.

الاسم والهوية لم يزود بهما المستخدم بعد؛ الحسابات في القالب غير مفعلة.
