# مدرسة معاذ بن جبل — بوابة شهادات المعلمين

GitHub Pages يستضيف صفحتي الدخول. تُعرض داخلهما واجهة Google Apps Script، وتنفذ الخدمة على حساب مالك المشروع. Google Sheets يحفظ الحسابات والسجلات، وGoogle Drive يحفظ الشهادات الخاصة. لا تحتاج هذه النسخة استضافة Node.js أو SQLite.

## الحالة الحالية

أُعدت الملفات واختبارات محلية بمحاكاة خدمات Google. لم يُنشأ مشروع Apps Script أو يُنشر بعد، ولم تنفذ تجربة رفع حقيقية أو مراجعة بصرية للتطبيق المنشور. رابط الخدمة في config.js فارغ عمدًا. المنظومة لا تستقبل بيانات حتى ينتهي التفعيل أدناه. ملف الحسابات لا يحتوي أسماء أو هويات فعلية.

## ملفات المدرسة

- المجلد: https://drive.google.com/drive/folders/1jUycH2hIsey_gq2AhN84BC7N_NA5g7Ws
- الشهادات: https://drive.google.com/drive/folders/1Gt9CVz3ZPDkEeekgi0tb0NdxSTRqLx9Z
- قاعدة البيانات: https://docs.google.com/spreadsheets/d/1MwFf-aMyI8SLN6S8EqNx76G6_Prr4QuRjhpR0Q0GcjU/edit

ملف Excel الأصلي خاص للتجهيز وتسليم كلمات المرور المؤقتة. لا يتزامن تلقائيًا مع Google Sheets. استخدم ورقة الحسابات في قاعدة البيانات لتفعيل الحسابات؛ يمكنك لصق الأسماء والهويات من Excel في الأعمدة المناظرة.

## التفعيل مرة واحدة من حساب مالك Drive

1. افتح قاعدة البيانات ثم Extensions → Apps Script.
2. استبدل Code.gs بمحتوى apps-script/Code.gs من هذا المستودع.
3. أضف ملف HTML باسم Portal وانسخ apps-script/Portal.html إليه.
4. أضف ملف HTML باسم Setup وانسخ apps-script/Setup.html إليه.
5. من إعدادات المشروع فعّل إظهار ملف appsscript.json، ثم استبدله بمحتوى apps-script/appsscript.json.
6. احفظ المشروع. اختر initialize_ من قائمة الدوال وشغّله، وفوّض المشروع من الحساب نفسه الذي يملك المجلد وقاعدة البيانات. ينشئ Users وCertificates وAudit ومفتاحًا سريًا في Script Properties. لا تشارك المشروع أو مفتاحه مع المعلمين.
7. عد إلى Google Sheets وأعد تحميل الصفحة. يظهر خيار «بوابة الشهادات» في القائمة.
8. في ورقة الحسابات، املأ اسم المسؤول وهويته ثم أسماء المعلمين وهوياتهم. الهوية عشرة أرقام وكلمة المرور المؤقتة 6 أحرف على الأقل. احفظ نسخة خاصة مكتملة من كلمات المرور المؤقتة لتسليمها فرديًا؛ التفعيل سيمسحها من Google Sheets.
9. اختر «بوابة الشهادات → تفعيل الحسابات المكتملة»، ثم «بدء التفعيل». تُشتق البصمات داخل المتصفح وتُرسل للتخزين؛ يلزم تغيير كلمة المرور عند أول دخول.
10. في محرر Apps Script اختر Deploy → New deployment → Web app. اختر Execute as: Me، وWho has access: Anyone إذا كان متاحًا وفق سياسة الحساب. الدخول داخل التطبيق يبقى بالهوية وكلمة المرور. إذا كانت سياسة المدرسة تمنع الوصول العام يلزم ضبط تصميم الدخول حسب سياسة المؤسسة.
11. انسخ رابط Web app الذي ينتهي بـ /exec، وضعه في appsScriptUrl داخل config.js، أو أرسله لاستكمال الربط. لا تستخدم رابط /dev؛ لا تضع أي كلمة مرور في config.js.
12. في GitHub Settings → Pages اختر GitHub Actions، ثم شغّل Publish school portal من Actions إن لم يبدأ تلقائيًا.

أدوات Drive المتصلة بهذه الجلسة تنشئ الملفات والجداول وتعدلها، لكنها لا تنشئ مشاريع Apps Script ولا تمنح تفويض التطبيق. لذلك خطوات الإنشاء والنشر والتفويض أعلاه تتطلب إجراءً من الحساب المالك.

## الروابط بعد نجاح النشر

- المعلم: https://coolmanx88.github.io/school-certificates/
- المسؤول: https://coolmanx88.github.io/school-certificates/admin.html

واجهة التطبيق تحتاج أن تُفتح من صفحتي GitHub. رابط Apps Script المباشر يخفي الواجهة عمدًا لحماية تضمينها؛ لا تعتمد فتح رابط /exec مباشرة كاختبار للواجهة. GitHub يشغّل غلاف الصفحة؛ المحتوى التفاعلي داخل إطار Apps Script. هذا يتجنب طلبات CORS غير المضمونة بين الخدمتين. لا تستبدل ذلك باستدعاء fetch مع no-cors، لأنه لا يتيح قراءة نتائج الحفظ.

## الصلاحيات

- المعلم: الدخول، تغيير كلمة المرور المؤقتة، إضافة دورة واحدة مع PDF، واستلام تأكيد. لا يستطيع قراءة قائمة الشهادات أو ملفاتها.
- المسؤول: الدخول، قراءة السجلات، البحث، مراجعة الحالة، تحميل PDF، وتصدير ملف Excel بصيغة XLSX.
- صاحب ملف Google Sheets: تفعيل حسابات جديدة وإعادة تعيين كلمات المرور من قائمة الجدول.

إعادة التعيين: اكتب كلمة مؤقتة جديدة في العمود D للصف المقصود، ثم اختر «إعادة تعيين كلمات المرور المحددة». تعالج هذه الوظيفة الحسابات الموجودة بنفس الصلاحية فقط، وتمسح الكلمة المؤقتة بعد نجاح العملية، وتلغي جلسات الحساب السابقة. لا تكتب كلمات المرور الحالية التي اختارها المعلمون في الجدول.

## حماية الحسابات والبيانات

- PBKDF2-SHA256 بعدد 600,000 دورة وsalt مختلف لكل حساب، عبر Web Crypto في المتصفح.
- بصمة مشتقة مع HMAC ومفتاح سري في Script Properties؛ أرقام الهوية في Users محفوظة كبصمات. ورقة الإدخال تحتوي الهوية الفعلية وتبقى خاصة بالمسؤول.
- رمز الجلسة في ذاكرة الصفحة فقط، وحد أقصى ساعتان؛ CacheService قد ينهيها مبكرًا. تغيير كلمة المرور يلغي الجلسات القديمة.
- تقييد محاولات الدخول، وصلاحيات تُفرض في الخادم، وقفل العمليات المتزامنة، ورفض تكرار الملف نفسه.
- لا تُنشر الملفات أو الجداول أو أسرار الحسابات. وظائف التهيئة المساعدة تنتهي بشرطة سفلية ولا تستدعيها google.script.run.
- غلاف GitHub يرفض عرضه داخل موقع آخر، وواجهة Google تبقى مخفية حتى تستقبل إقرارًا من نافذة GitHub العليا. يلزم اختبار هذا المسار في المتصفح بعد النشر.
- الحد البرمجي للملف 25 MiB؛ النقل يستخدم Base64. يحتاج هذا الحجم إلى اختبار حقيقي بعد النشر للتأكد من حدود RPC وزمن التنفيذ. المحاكاة لا تثبت قبول ملف بهذا الحجم على Google.
- فحص توقيع PDF لا يمثل فحصًا كاملًا للملف أو للبرمجيات الضارة.
- Google Apps Script يخضع للحصص وحدود التنفيذ. راقب زمن الرفع والأخطاء بعد التجربة، وحدد سياسة نسخ احتياطي للجدول والشهادات.

## اختبار القبول قبل التعميم

1. فعّل حساب مسؤول وحساب معلم تجريبيين من البيانات المعتمدة.
2. تأكد أن أول دخول يفرض تغيير الكلمة، وأن المعلم لا يرى السجلات.
3. ارفع PDF صغيرًا؛ تحقق من ظهور سجل واحد وملف في مجلد الشهادات.
4. ارفع الملف نفسه مجددًا؛ يجب رفضه دون إضافة ملف جديد.
5. افتح الشهادة من حساب المسؤول، غيّر حالتها، وصدّر Excel.
6. اختبر رفض ملف غير صالح، والملف الأكبر من الحد، والساعات والتاريخ غير الصالحين.
7. اختبر الهاتف والكمبيوتر، ونفّذ تجربة بخمسة معلمين قبل التعميم.
8. تحقق من خصوصية المجلد والجدول وطريقة النسخ الاحتياطي والاستعادة.

## تعديل التطبيق لاحقًا

عدّل portal.html وapp.js وexport-xlsx.js وstyle.css، ثم شغّل:

```sh
node scripts/build-apps-script.mjs
node scripts/test-apps-script.mjs
```

انسخ Portal.html المحدث إلى مشروع Google. عند تعديل Code.gs أو Setup.html حدّث النسخة في Google أيضًا. ثم اختر Deploy → Manage deployments → Edit → New version للحفاظ على رابط /exec نفسه. رفع الكود إلى GitHub لا يحدّث مشروع Apps Script تلقائيًا.

وثائق Google: https://developers.google.com/apps-script/guides/web و https://developers.google.com/apps-script/guides/html/communication و https://developers.google.com/apps-script/guides/services/quotas

## تنظيم ملفات الشهادات

عند الرفع ينشئ التطبيق مجلدًا لكل معلم داخل «الشهادات»، ويحفظ PDF باسم عنوان الدورة. يعيد استخدام المجلد نفسه، ويضيف معرّفًا داخليًا قصيرًا فقط إذا تكررت أسماء المعلمين. لا يستخدم رقم الهوية في اسم المجلد. الأحرف غير المناسبة لمسارات الملفات مثل / و\ تستبدل بمسافة، ويضاف الامتداد .pdf مرة واحدة. إذا تشابه عنوان شهادتين مختلفتين فقد يظهر ملفان بالاسم نفسه في Drive؛ سجلاتهما ومعرّفاتهما تبقى منفصلة.

لتنظيم الملفات التي رُفعت قبل التعديل: بعد تحديث Code.gs، أعد تحميل قاعدة البيانات، ثم اختر «بوابة الشهادات → تنظيم الشهادات السابقة». ينقل الملفات ويعيد تسميتها مع الحفاظ على معرّف الملف وروابط السجل. يعالج حتى 30 تغييرًا في المرة، ويعرض عدد الباقي والأخطاء. شغّله مجددًا إذا بقيت شهادات. لا يُطلب إعادة رفع الشهادات.

اسم مشروع Apps Script في Google يُغيّر يدويًا إلى «بوابة مدرسة معاذ بن جبل»، ووصف النشر يمكن تعديله عند نشر الإصدار الجديد. معرّفات المجلد والجدول ورابط /exec لم تتغير.

## تصدير نتائج البحث

زر «تصدير Excel» في صفحة المسؤول يحفظ نتائج البحث والتصفية الظاهرة لحظة الضغط فقط، وبترتيب العرض نفسه. الملف XLSX حقيقي باتجاه RTL، وله سبعة أعمدة مثل الشاشة: المعلم، الدورة / الجهة، التاريخ، الساعات، المجال / السنة، الحالة، اسم الشهادة. تُكتب الجهة والسنة في سطر ثانٍ داخل خليتيهما، ويظهر عنوان الشهادة بامتداد PDF بدل زر فتح الملف. ملف Excel لا يحتوي ملفات PDF نفسها أو هويات المعلمين وكلمات مرورهم.

يُنشأ الملف في متصفح المسؤول. تُحمّل مكتبة ExcelJS 4.4.0 من jsDelivr عند أول تصدير، مع التحقق من بصمة SRI ثابتة؛ لا تُرسل نتائج البحث إلى خدمة إنشاء ملفات. يحتاج أول تصدير اتصالًا متاحًا لتحميل المكتبة.
